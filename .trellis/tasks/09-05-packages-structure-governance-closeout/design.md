# Packages 全仓结构治理收尾设计

## 任务边界

父任务不修改生产代码。它将审计、实现和最终门禁过程中确认的十一个独立交付映射到十一个子任务，并在子任务全部完成后执行跨包集成验收。

## 执行关系

```text
发布合同 -> ownership collector -> 包内模块循环 -> workspace 包循环
                                     |
             +-----------------------+-----------------------+
             |                                               |
             v                                               v
 Workbench P2 / AI discovery                         Sass 与 Workbench 样式 owner
             |                                               |
             +-----------------------+-----------------------+
                                     v
                               全仓集成验收
```

- 发布合同子任务优先完成，因为它补充的静态门禁会成为后续全仓验证的一部分。
- collector 子任务随后完成，以便后续移动文件时由更完整的所有权规则护航。
- 两个服务拆分、AI discovery 与样式 owner 子任务边界独立，在 collector 稳定后分别实施。
- 包内模块图与 workspace manifest 图分别设门禁，避免把两种依赖环混为一个分析层。
- Element 默认值控件的一致性修复作为 Sass/defaultValue 子任务的独立回归交付，不混入 Shell 样式迁移提交。
- 根 typecheck 发现的 Headless 异构 slot attrs 推导缺陷作为独立公共类型修复，不用 adapter 测试断言或类型断言绕过。

## 兼容策略

- 保留所有包根导出、公开函数签名、组件行为和运行时协议。
- 内部移动通过最近的责任 barrel 暴露，不新增旧路径 forwarding shim。
- 架构规则若发现存量误报，优先修正分析语义；仅对真实动态或框架入口使用精确 manifest 例外。

## 提交与回滚

- 每个子任务一个或多个边界清晰的独立提交，并在门禁通过后归档。
- 某个子任务失败时仅回退该子任务的未提交改动，不影响已完成子任务。
- 父任务最终只提交任务归档和必要的跨子任务文档更新。
