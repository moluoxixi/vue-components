# 产品定位

ConfigForm 服务两种开发场景：开发者在业务代码中编写配置化表单，以及通过可视化设计器
搭建真实组件界面并交付源码。两条路径共享字段、布局、校验等能力，各自保持完整的使用体验。

## 代码态表单

Runtime 首先服务 Vue、Element Plus 和 Ant Design Vue 开发者。字段配置是普通 TypeScript，
支持类型推导、组件 props、函数条件、异步校验和宿主业务事件。模型由业务应用拥有。
使用者不必创建 Studio 项目，也不必理解 Model、Compiler、IR 或 MCP。

这一场景的成功标准是：复制最小示例即可使用；模型回显、校验、提交、重置、只读和嵌套
作用域有一致语义；真实业务逻辑可以自然地写在代码里。设计器的可序列化约束不能限制 Runtime。

## 可视化设计与源码交付

Studio 服务希望通过真实组件快速搭建表单、查询、详情、弹窗和抽屉的开发者。
用户从“创建表单”选择模板即可进入设计，项目自动创建；多个页面仍可按项目管理。
设计器默认交付独立 Vue 工程，也提供接入现有 Runtime 项目的 ConfigForm 绑定代码。

项目 JSON 是 Studio 的设计源文档。可视化操作和 AI 编辑使用同一套模型、校验与事务；
预览和源码都是这份文档的投影。它与运行时手写配置有明确边界，不承诺导入带函数的任意配置。

## 用户与任务

设计者不应为了调整字段、校验或常见 UI 属性而理解 JSON 路径、编译结构或仓库协议。
属性面板优先呈现字段与数据、布局，再提供通用视觉样式。

典型过程：

1. 从空项目、模板或 AI 提议开始创建界面。
2. 在真实组件上调整布局、尺寸、间距、文案与外观。
3. 用示例数据、校验和受控本地交互体验设计。
4. 保存项目，重新打开后继续修改。
5. 生成、查看和导出可独立维护的 Vue 源码。

成功标准是从设计到源码接手顺畅，预览与生成结果保留受支持的设计决定；保留项目 JSON
后能够重开并继续设计。生成物应带运行或集成说明，不能把绑定代码包描述为独立应用。

## 设计资产

项目包含页面、弹窗、抽屉、示例 Dataset、图片等 Resource，以及项目主题。
Page、Dialog、Drawer 是可独立设计和复用的 Surface；每次体验打开时创建隔离的实例。
Material 描述可使用的真实组件及其可编辑能力。

设计文档需要表达布局约束、主题和受控交互等设计意图，它不只是组件节点树。
当前断点能力用于已支持的表单布局；节点级响应式样式、组件定义与实例变体仍需后续
设计，不能把这些规划写成当前能力。

## 动态能力

配置优先不等于只能设计静态画面。当前支持表单响应式布局、安全表达式状态投影、
`set/copy/clear` 值动作，以及导航、打开和关闭浮层等单一主要 UI 动作。
字段 Required、RuleSet v2 和本地 Dataset 用于可确定的体验与生成。

这些能力具有明确的设计含义。任意 JavaScript、生产接口、鉴权、异步副作用与复杂业务
函数继续由工程师在普通 Vue/TypeScript 中维护。Studio 不据此推断或重写生产业务逻辑。

## 源码交付

默认交付原生 Vue 工程，使用 Vue、Vue Router 和目标 UI 库，可脱离 Studio 继续开发。
CSS 与 Tailwind v4 均可选，后者的部分校验会使用 Zod，以生成的 `package.json` 为准。
ConfigForm 绑定产物是用于已有应用的配置与组件代码包；先展示当前页面配置，宿主负责接入。
源码生成必须保留所支持的布局、视觉、数据、
校验与本地交互，不能靠静默省略获得成功结果。

交付当前是单向的。手改源码不会自动更新设计文档，后续设计导出也不自动合并到手改工程。
[源码导入提案](./source-import.md)保留为历史研究边界，不作为当前收尾或归档的前提。

## 边界

- 优先使用 Grid/Flex、尺寸约束和断点，不建设绝对定位自由画布。
- 不在设计文档中执行任意脚本，不建设任意 CSS 编辑器、通用 Flow、事件总线或动作编排器。
- Dataset 是设计示例数据，不冒充生产 Runtime 的 Data Source。
- 当前提供浏览器本地保存和文件工作区，不承诺云端发布或实时多人协作。
- 生产 Runtime 保持独立；代码态配置、宿主函数和真实数据接入继续受其自身 API 支持。

产品改动应优先减少常见设计任务中的操作成本，并通过多轮修改、重开项目和源码交付验证。

## 收尾范围

目前作为个人工具和技术积累维护，尚无持续使用者。以两条开发路径可运行、可理解、可接手
为归档标准。保留现有功能和 SDK/MCP，完成实际问题修复与验证后冻结功能范围。
新的页面类型、协作、源码回导及更广的可视化业务编排，需要明确使用场景后再单独评估。
