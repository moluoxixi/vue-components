# 实施计划

## 目标与现有基础

目标是让用户持续维护一个真实组件 UI 设计项目：设计修改保存到配置，预览和 Vue 源码
保留同样的设计决定。生产 Runtime 的宿主业务能力保持独立。

当前基础已经包括 Page/Dialog/Drawer、Dataset/Resource、项目主题、表单响应式布局、
属性与校验编辑、受控本地交互、保存恢复、原生 Vue 生成、Studio SDK、本地工作区和 MCP。
这些是本轮改进的基础，不作为新完成的能力重复申报。

## 本轮：通用视觉编辑与投影一致性

本轮方案沿用 `props.style` 和当前项目合同，增强直接设计 UI 的能力。实施范围：

- 提供跨组件的通用视觉面板，覆盖尺寸、间距、外观和排版，常见修改无需编辑 JSON。
- 复用属性命令和事务，支持多选修改、撤销重做、自动保存与重开恢复。
- 编辑对象形式的 style 时保留其他键；非对象和受支持属性的 kebab-case 别名保持受限
  只读，避免静默覆盖或产生冲突写法。
- 修复源码生成中布局样式覆盖用户 style、属性排序改变 CSS 声明优先级的问题，核对
  Compiler、预览、Raw 和 ConfigForm binding 产物的同一视觉语义。
- 校验合法值、清空、非法中间态、命令拒绝，以及小屏和键盘操作。

不新增 `node.design`，不升级 Model 版本，不引入来源映射、区域能力或任意表达式合同。
本轮不是节点级响应式样式编辑；现有断点能力只覆盖已支持的表单布局。
执行结果在完成后记录到 [验证文档](./verification.md)。

## 验收项目

使用“成员列表＋编辑抽屉”或同等复杂度的真实组件项目完成连续修改：

1. 创建页面与抽屉，配置示例数据、字段和校验，保存后重开。
2. 调整尺寸、间距、外观和排版，检查真实预览，确认其他属性不丢失。
3. 多选修改、撤销和重做，再刷新或重新打开项目，确认视觉值保留。
4. 体验筛选、打开抽屉、输入校验和关闭路径。
5. 检查既有表单断点布局，确认本轮静态 style 不被误认为节点断点覆盖。
6. 生成源码，独立类型检查和构建，核对用户视觉值与布局组合结果。

验证覆盖双组件库及 CSS / Tailwind，不能用生成字符串快照代替真实运行结果。

## 后续顺序

| 顺序 | 工作                                 | 进入条件                                             |
| ---- | ------------------------------------ | ---------------------------------------------------- |
| 1    | 扩充必要的视觉与布局操作             | 真实项目出现反复绕过工具的设计修改                   |
| 2    | 节点级响应式样式、设计状态和组件变体 | 能定义继承、实例覆盖、复用关系与导出语义             |
| 3    | 改善交付工程接入与源码差异审核       | 用户反复导出，并能指出具体接入成本                   |
| 4    | 受限的外部源码导入                   | 前述链路稳定，且有明确导入样本和保存、预览、导出边界 |

未来源码导入以 [source-import.md](./source-import.md) 为边界提案。先用包含动态 style、
循环、条件与插槽的样本评估，不把任意双向源码编辑列为产品成立的前提。
