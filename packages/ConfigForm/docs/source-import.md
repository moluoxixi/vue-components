# 未来源码导入

状态：边界提案，尚未实现，不是当前导入 API 或持久化合同。

未来可以解析已有 Vue 源码，将可识别结构转换为新的设计项目。AST 是分析与生成的手段，
配置仍是导入完成后的设计源文档。该能力不承诺手改源码与配置持续双向同步。

## 分析结果

| 源码情况                               | 设计器行为                       | 必须保留的信息             |
| -------------------------------------- | -------------------------------- | -------------------------- |
| 能完整表达的结构和属性                 | 正常编辑                         | 转换结果及来源             |
| 某个属性由不可转换表达式控制           | 对应属性只读，其他独立属性可编辑 | 控制原因、来源、表达式信息 |
| 子树依赖循环、条件、作用域插槽等上下文 | 按最小完整上下文显示只读区域     | 区域边界、依赖和来源       |
| 无法在设计环境预览                     | 显示明确占位，不静默隐藏         | 缺失原因、来源和影响范围   |

可解析不等于可编辑。分析需要判断独立修改是否破坏上下文，必要时将只读范围扩大到
组件或整个子树。不得只因节点文字和颜色是静态的，就允许它移出原有循环或插槽作用域。

例如 `:style="{ width: getWidth(user, viewport) }"` 能被 AST 解析，但拖动宽度并不能唯一
决定应改函数、参数还是新增覆盖。未经明确转换规则时，宽度保持只读；不能把某次运行
得到的像素值默认为静态设计宽度。

## 编辑与预览

- 以属性、上下文区域和预览能力分别说明限制，避免整页无差别锁定。
- 只读原因可定位到来源，不把原始 AST、内部路径或分析协议作为主要操作界面。
- 受限区域保留位置和可识别边界；无法渲染时使用占位，不能造成完整导入的错觉。
- 导入报告列出已转换、只读和无法预览项；用户能在继续设计前判断是否可用。
- 原始源码可以作为导入附件保留，不能因此在配置中执行任意 JavaScript。

未来设计应使来源信息与编辑能力有明确所有者，并覆盖复制、移动、删除和组件复用后的
行为。本轮只确认这些要求，不提前添加空字段、隐藏开关或备用运行时分支。

## 导出边界

保留源码和表达式信息，不等于保留原运行行为。保留动态组件还需要处理组件、依赖、
样式、数据和运行上下文，不能仅通过禁用属性控件宣称支持。

受限区域的交付只能选择显式且可验证的行为：

- 能安全保留组件引用和完整依赖时，输出该引用并报告需要的宿主条件。
- 只能交付可编辑部分时，明确标为部分产物，并列出缺失区域，不能作为完整工程成功导出。
- 无法保证完整性时，阻止完整导出并返回可定位诊断。

占位不能悄悄进入最终工程替代业务区域，动态表达式不能静默删除或固化。
预览可用、属性可编辑和工程可独立运行是三项独立能力，诊断必须分别表达。

## 实施前验证

至少使用以下 Vue 样本验证最小能力范围：静态组件、静态与动态混合的 style、条件分支、
`v-for`、作用域插槽和自定义组件。每个样本检查导入报告、编辑限制、占位、保存重开和
生成产物；不能仅以“AST 解析成功”验收。

详细协议、文件保存方式和依赖打包策略在实施时单独设计并版本化。当前仍以
[配置创作与单向交付](./product.md)为主链。
