# ConfigForm Workbench 模板创建页精修

## 目标

把 ConfigForm Workbench 模板创建页精修为可扫描、可比较、响应式稳定的创建工作区，让用户能够快速筛选模板、理解适配资格、检查真实预览并安全创建项目。

## 上下文

- 父任务：`09-02-config-form-workbench-ui-polish`。
- 当前宽屏使用目录/详情双栏，900 像素仍保留 300 像素目录导致预览拥挤；390 像素使用目录/详情单窗格。
- 当前目录加载失败与筛选无结果共用空态，无选中模板时详情区为空；搜索、筛选、键盘导航、资格校验与创建状态流已有测试合同。

## 需求

1. 采用自适应主从布局：宽屏为紧凑目录加详情/真实预览；641–1000 像素为窄分类栏加按需目录并以详情/预览为主；640 像素及以下用成熟分段控件切换目录和详情。
2. 移动端默认进入目录；选择模板后可清晰进入详情，返回和 Escape 行为保持可预测。
3. 目录以紧凑列表表达名称、类别、适配器/Provider 与资格状态，保留搜索、类别筛选、Provider Select 与 roving keyboard navigation。
4. 分离目录加载失败、筛选无结果、无选择、资格失败、预览失败与创建中状态，为每种状态提供准确文案和下一步动作。
5. 详情保留模板身份、适配器/Provider、资格信息、真实 Runtime iframe 与 sticky 创建区域；预览区域在 900 像素不得被目录挤压或遮挡。
6. 使用父主题任务的语义 token 和 Element Plus 成熟控件；不构建模板市场式卡片网格，不增加无依据的缩略图、营销文案或装饰。
7. 不改变模板数据契约、筛选语义、选择状态、adapter 加载、资格校验、预览 race 防护、创建禁用条件和重复提交防护。

## 验收标准

- [ ] 宽屏、900 和 390 像素呈现约定的主从、窄栏与单窗格布局，无横向滚动、截断、遮挡或底部创建区覆盖内容。
- [ ] 目录失败、空筛选、无选择、资格失败和预览失败可被用户明确区分并完成恢复。
- [ ] 搜索、分类、Provider 筛选、键盘选择、移动返回、真实预览、创建阻断和成功创建路径全部回归通过。
- [ ] 四套配色的 Light/Dark 均可正确渲染模板页与 overlay；Runtime iframe 样式不随壳主题变化。
- [ ] 模板专项单测/E2E、axe、视觉截图、Workbench typecheck/build、lint 与 `git diff --check` 通过。

## 范围外

- 增加远程模板市场、模板下载、评分、付费、缩略图生成或新的模板数据字段。
- 修改 JSON 导入工作流的数据语义或项目创建事务合同。
- 修改 Runtime Provider 主题或把 Workbench token 注入预览 iframe。
