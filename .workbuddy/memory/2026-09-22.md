## 排查「Stored project manifest is invalid.」与项目管理/页面管理可见性

- 报错来源：`packages/ConfigForm/workbench/src/project/persistence/adapters/indexed-db-project-codec.ts:247`
  `parseStoredManifest` 校验 `{checksum,receipts,snapshot,version,versions}` 且
  `version === PROJECT_MANIFEST_VERSION(4)`，否则抛
  `ProjectRepositoryError('PROJECT_REPOSITORY_CORRUPT', 'Stored project manifest is invalid.')`。
  这是硬切合同（ROADMAP：IndexedDB manifest/entity codec 3→4，无迁移器）拒绝旧数据的设计行为。
- 放大问题：`indexed-db-repository.ts` 的 `list()` 对每个 id 调 `get()`，任一条旧记录解析失败会让
  整个项目列表 reject；`initializeRepository → refreshProjects()` 抛出后由
  `useWorkbenchControllerLifecycle` 捕获 → `ui.notify` → 项目首屏显示红色 ElAlert + 空列表。
  修复方向：list() 跳过并上报损坏记录，而不是整体失败。
- 用户可见性结论（功能其实都在）：
  - 项目管理 = `src/features/projects/index.vue`（App.vue `view==='projects'` 首屏）
  - 页面管理 = `src/features/pages/components/SurfaceManager/index.vue`（app/index.vue 懒加载弹窗），
    入口：顶栏「管理界面」、左侧面板「管理页面」、移动端 dock「页面」tab
- 发现的文案缺陷（待确认是否修复）：
  1. 整个 locale 目录没有 `projects.*` 词条，项目管理首屏在 zh-CN 下全英文
     （Projects / New project / Import JSON / No projects yet）。
  2. `surfaces.manage` 中文译成「管理界面」（应为「管理页面」），与 `pages.manage`「管理页面」
     指同一个弹窗，两处标签不一致。
  3. `pageManager.title` zh 为「页面」，en 为 Surfaces。
- 校验流程注意：`src/locale/__tests__/locale.test.ts` 断言 en/zh 词条 key 完全一致，
  新增 `projects.*` 必须两个 catalog 同步加。

## Workbench/Studio 应用壳改造为真正的路由应用

用户确认的三项决策：**hash 路由**、**页面管理改成独立整页**、**在 workbench 包内改造**。

### 新增/改动

- `src/app/router/`（feature root，根目录只放 index.ts + types/services 子目录）：
  `createWorkbenchRouter()` = `createRouter({ history: createWebHashHistory(base ?? location.pathname) })`。
  路由表：`/`→`/projects`；`/projects`(projects)；`/projects/new`(project-create)；
  `/projects/import`(project-import)；`/projects/:projectId/design`(project-design)；
  `/projects/:projectId/design/:surfaceId`(surface-design)；`/projects/:projectId/pages`(project-pages)；
  `/projects/:projectId/create`(surface-create)；catch-all→`/projects`。
  静态段 `/projects/new|import` 只有两段、项目路由都是三段，因此永不冲突。
- `src/app/router/services/index.ts`：`resolveWorkbenchSurfaceTarget`（请求的 Surface 缺失/缺省时回退首页）、
  `shouldBlockProjectSwitch`（dirty/configError + 切到别的项目 → 拦截）。
- `src/app/composables/use-workbench-route-sync.ts`：URL 是"哪个项目/哪个 Surface 打开"的唯一来源。
  注意两个坑：① 只有设计路由才做 URL 归一化，否则页面管理会被拽回设计路由；
  ② 会话快照可能还没含新建 Surface，所以 requested === currentSurfaceId 时必须直接信任，不能只看 document。
- `src/app/composables/use-creation-return-focus.ts` + ui-store 的 `creationOrigin`（替换原 pageManagerOpen/
  pageManagerLoaded/openSurfaceManager/closeSurfaceManager）：取消创建 → 回 origin.path 并聚焦
  `[data-create-trigger=<key>]`；创建成功 → 进新项目/Surface 并聚焦 `[data-designer-entry]`。
- `App.vue` = provide + `<RouterView>` + 外观抽屉；`app/index.vue`(WorkbenchShell) 降级为设计器路由视图；
  新增 `app/components/{ProjectsView,CreationView,DesignView,PagesView}.vue`（不进 components barrel，避免循环）。
- `features/pages/index.vue` 改为整页 `SurfaceManagerPage`（props 加 palette/theme，不再用 ElDialog）；
  创建入口仍靠 props/emits 传递，**features 一律不 import vue-router**（已加架构门禁断言）。
- 浏览器行为：`/` 与未知深链 → `/projects`；深链刷新/分享/前进后退都还原同一项目+Surface；
  项目脏时切项目被拦并提示；`initializeRepository` 不再自动打开首个项目（路由决定）。
- locale：`pageManager.close`→`pageManager.back`(返回设计器)；删除 `surfaces.manage`（中文旧译"管理界面"），
  统一用 `pages.manage`（管理页面）。
