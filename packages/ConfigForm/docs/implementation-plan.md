# 收尾计划

## 目标与边界

ConfigForm 保留两个各自完整的开发入口：

- **代码配置表单**：开发者直接使用 Runtime 和 UI adapter，在 TypeScript 中定义字段、模型、校验、联动和宿主事件。无需设计器、项目文档或编译器。
- **可视化转源码**：在设计器选择模板、编辑真实组件、体验交互，再交付可独立维护的 Vue 源码。需要 ConfigForm 的现有项目可选择绑定代码。

两条入口共享底层表单能力，但不要求用户先理解整套 Studio 架构。设计 JSON 用于继续设计；源码交付是单向生成，手改源码不会回导，也不会在重新导出时自动合并。

当前基础已有 Page/Dialog/Drawer、Dataset/Resource、主题、响应式表单布局、通用视觉属性、统一 Inspector、撤销重做、保存恢复、原生 Vue 生成、Studio SDK、本地工作区和 MCP。收尾保留这些能力，不将它们重复申报为本轮新增。

## 本轮改进

1. 明确两个开发入口，修正 Runtime 入门示例、数组/对象作用域和提交插槽说明。
2. 提供“创建表单”捷径：选择模板后自动建立项目并直接进入设计；保留空项目与多页面管理入口。
3. 调整属性面板顺序，将字段、标签和数据属性放在通用视觉样式之前；修复必填标记重复。
4. 原生 Vue 保持默认交付。ConfigForm 模式优先打开页面配置，并明确绑定代码不含独立应用入口。
5. 两类源码包附带对应接入说明；设计 JSON 提供直接保存入口，提示再编辑和源码交付的边界。
6. 补齐本轮涉及的禁用操作提示、创建/交付页面间距，核对双组件库、桌面与小屏体验。
7. 修复工作台首次开发启动缺少依赖产物的问题，完成验证并记录实际结果。

## 验收项目

| 场景            | 验收条件                                                                                                          |
| --------------- | ----------------------------------------------------------------------------------------------------------------- |
| 手写配置        | Element Plus / Ant Design Vue 文档入口清楚；字段 ID、模型、校验、提交与宿主责任符合公开类型；Runtime 不依赖设计器 |
| 快速开始        | 两种组件库均能从模板直接创建设计，正确持久化并能重开；原有空项目/多页面路径仍可使用                               |
| 编辑与体验      | 常用字段属性优先可见，视觉属性仍可修改；撤销重做、保存恢复和表单校验可用；必填标记只出现一次                      |
| Vue 源码        | 默认显示页面组件；CSS / Tailwind 产物可独立类型检查和构建；不依赖 ConfigForm Runtime                              |
| ConfigForm 绑定 | 默认显示页面配置；提供正确的依赖、模型、样式及宿主 actions 接入说明；明确其为集成代码包                           |
| 设计留存        | 保存的设计 JSON 可继续在设计器编辑；不把源码 ZIP 或 Runtime TypeScript 配置宣称为可回导设计文件                   |
| 界面            | 主要操作在桌面与小屏可达，禁用原因可见，头部与内容有清晰间距                                                      |
| 工程            | 相关单测、类型检查、构建、生成消费者与包边界检查通过；记录真实执行结果和未覆盖项                                  |

验证方法和本轮结果记入 [验证文档](./verification.md)。

## 冻结条件

本项目目前主要用于个人工具和技术积累，没有持续使用者。上述路径通过后进入功能冻结，保留缺陷修复和必要的依赖维护，不继续按假想平台需求扩展。

协作平台、任意页面搭建、节点级响应式设计系统、任意源码双向转换均不作为归档前置条件。[源码导入研究](./source-import.md)保留为历史边界分析，不是待兑现的产品承诺。只有出现具体使用场景、样本和明确收益时，再独立评估是否重启。
