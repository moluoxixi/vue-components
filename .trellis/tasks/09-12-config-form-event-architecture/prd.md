# 重构配置化表单与设计器事件体系

## 目标

参考 form-create 重写配置化表单设计器的事件流程，使设计、预览、独立运行和导出具有一致、可诊断的事件行为，并修复影响表单和设计器成熟度的架构问题。

## 已确认约束

- 项目仍处于架构探索阶段，无需兼容旧事件协议或旧代码逻辑。
- 用户授权根据代码和参考实现判断并优化不合理之处。
- 主代理负责方案、代码修改和最终验证；子代理仅探索与核验。

## 需求

- R1：研究 form-create 的组件事件、上下文注入、表单 API 和设计器配置方式，形成有出处的设计依据。
- R2：建立清晰的事件定义、绑定、执行、状态更新和错误报告契约。
- R3：统一设计器预览、配置化表单运行时与导出行为。
- R4：事件编辑支持可靠的新增、修改、删除和校验，失效配置可被发现。
- R5：覆盖异步执行、重复触发、销毁清理、字段联动与失败恢复。
- R6：同步更新示例、测试和相关开发文档。

## 验收标准

- [x] 有 form-create 对照证据与完整技术方案。
- [x] 事件配置到运行时执行及导出闭环通过集成验证。
- [x] 设计模式不会触发业务副作用，预览行为与独立运行一致。
- [x] 关键异步与错误边界有回归测试。
- [ ] 相关类型检查、单元测试、构建及浏览器主要工作流验证通过。
- [x] 记录剩余限制，并提供可访问的本地设计器地址。

完整门禁中的剩余限制见 implement.md：Windows 截图基线缺失，以及两个非 ConfigForm 包的既有架构违规；功能、类型、构建与双 Provider 导出验证已通过。
