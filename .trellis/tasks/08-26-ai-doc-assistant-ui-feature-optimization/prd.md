# AI 文档助手界面与功能优化

## 目标

把 `packages/ai-doc-assistant` 从“对话页叠加知识库弹框”优化为面向组件库开发者的稳定工作区，使用户能在桌面端和移动端高效完成提问、阅读结构化回答、追溯来源、浏览组件契约和继续追问，同时修复长对话与流式状态的确定性缺陷。

## 背景

- 当前应用没有路由或全局状态层，跨视图状态集中在 `src/ui/App.vue:17-42,231-258`；对话常驻，知识库总览与详情共用 `ElDialog`。
- 实际页面验证显示，宽屏对话首屏存在大量无效空白；复杂组件详情在桌面端形成约 1.6 万像素高的弹框，在移动端约 1.9 万像素高，无法形成稳定、可扫描的工作区。
- 用户已选择推荐范围：重构核心工作区，并纳入 Markdown、响应式、状态反馈、键盘可达性、历史裁剪与清空；会话和知识库持久化延期。

## 需求

### R1 工作区与信息架构

- “问答”和“知识库”应成为同一应用壳内的两个一级视图，知识库不再依赖超长弹框。
- 切换视图时必须保留当前对话及生成状态；组件详情返回总览、来源打开详情、详情发起追问等现有工作流保持可用。
- 顶栏只突出产品身份、一级视图、可操作的知识库状态和必要命令；`content`、`ready`、provider 等内部枚举不得以同权重调试信息常驻首屏。
- 桌面端内容应有稳定的阅读宽度和独立滚动区；移动端不得出现页面级横向溢出，输入区和主导航必须始终可达。

### R2 结构化且安全的 AI 回答

- AI 回答的文字分段应渲染标题、列表、引用、链接、行内代码和非 Vue fenced code，而不是显示 Markdown 原文。现状证据：`src/core/vue-block-extractor.ts:110-166`、`src/ui/views/ChatView.vue:242-267,426-428`。
- 现有 Vue fenced block 仍按原位置交给 `DemoPreview`，不得被 Markdown renderer 吞并或重复渲染。
- LLM 原生 HTML 必须作为文本展示；危险 scheme 和事件属性不得进入可执行 DOM；外部链接必须使用安全的新窗口属性。
- 流式未闭合 Markdown 不得导致渲染异常，回答完成后应恢复正确结构。

### R3 对话可靠性与效率

- 请求历史必须按完整问答对保留最新连续后缀，同时满足最多 20 条消息和 20,000 个 JavaScript 字符；不得拆分问答对。现状边界：`src/ui/views/ChatView.vue:87-94,147`、`src/server/router.ts:29-32,92-111`。
- 用户可以清空当前内存会话；若正在生成，应先使当前请求失效并中止，再清空界面，下一问不得携带旧历史。
- 只有收到 `done` 终态才能将回答标记完成；未收到 `done/error` 就结束的 SSE 流必须显示为异常中断，不得把残缺回答加入后续历史。
- 流式自动滚动只在用户仍靠近底部时保持跟随；用户主动查看旧内容时不得被每个 token 拉回底部，并应提供回到最新内容的入口。
- 来源信息应展示协议已有的组件、包、来源类型、路径和相关度；缺失的可选字段应优雅降级。协议证据：`src/shared/protocol.ts:56-65`。

### R4 状态、反馈与可访问性

- 首次连接、索引构建、组件列表加载、空列表、加载失败和重试必须是可区分状态，不得把“尚未返回”展示成“知识库为空/未构建”。现状证据：`src/ui/App.vue:27-39,151-183,227-229`、`src/ui/views/OverviewView.vue:70-72`。
- 关键异步状态使用 `role="status"` 或合适的 `aria-live`，错误使用 `role="alert"`；流式 token 本身不得造成整段回答反复播报。
- 导出格式菜单必须支持打开后聚焦、方向键、Home/End、Escape、点击外部关闭和焦点归还；优先使用 Element Plus 已提供的可访问浮层能力。导入当前只有一个 JSON 命令，使用可聚焦的直接上传按钮，不额外制造单项菜单。现状证据：`src/ui/App.vue:187-204`、`src/ui/views/OverviewView.vue:93-121`、`src/ui/views/DetailView.vue:123-149`。
- 详情中的类型定义入口必须可被键盘和触屏访问。现状证据：`src/ui/views/DetailView.vue:199-357`。
- 命令图标使用一致的 Lucide 图标与 tooltip，不再使用平台字形不一致的 emoji。

### R5 知识库浏览效率

- 总览应保留搜索、结果计数、组件来源和导出，并新增明确的加载/错误/空结果状态。
- 详情页应在桌面与移动端提供清晰的组件身份、返回、追问和导出操作；长契约区块可快速定位，表格在自身容器内横向滚动，不放大整个工作区。
- 类型定义、Props、Emits、v-model、Slots、Attrs、Exposed 等现有契约数据必须完整保留。

### R6 验证与门禁

- 单元测试覆盖 Markdown 安全、历史双边界、清空竞态、异常断流、状态语义、菜单键盘和自动滚动。
- 浏览器 E2E 覆盖 `1440x900` 桌面视口和 `390x844` 移动视口，并验证无页面级横向溢出、核心操作可达和问答/Demo 主链路。
- AI 文档助手 E2E 必须进入仓库常规 browser CI 门禁。现状缺口：`__e2e__/ui-flow.e2e.test.ts:157-233`、`.github/workflows/ci.yml:96-106`。

## 验收标准

- [x] AC1：问答与知识库可作为一级视图切换，切换期间对话内容和正在进行的请求不丢失。
- [x] AC2：桌面与移动视口中主工作区占满可用高度，知识库详情不再生成超长弹框，页面级 `scrollWidth <= innerWidth`。
- [x] AC3：Markdown 标题、列表、引用、链接和代码块结构化显示；原生 HTML、事件属性及危险链接不能执行，Vue Demo 仍原位工作。
- [x] AC4：第 11 对及更长对话仍能正常提问，发送历史始终满足 20 条/20,000 字符且保持完整问答对。
- [x] AC5：清空会话会中止进行中的请求并移除旧历史；异常断流显示错误而不是完成。
- [x] AC6：连接、构建、加载、空、错误和重试状态在视觉与辅助技术语义上可区分。
- [x] AC7：所有菜单和类型提示可通过键盘操作，Escape 后焦点返回触发器；移动端触屏可访问等价信息。
- [x] AC8：用户上滚阅读时流式回答不强制跳底，回到最新入口可恢复跟随。
- [x] AC9：现有索引构建、导入、JSON 导出、来源跳转、组件详情、问 AI、流式回答和 Demo 预览回归通过。
- [x] AC10：包级 lint、typecheck、单测、coverage、build、桌面/移动 E2E 与浏览器实际截图检查全部通过，CI 已纳入 AI 文档助手 E2E。

## 技术约束

- 保留 Vue 3、Element Plus、Vite 与现有 BFF/SSE 协议；不引入路由或全局状态库。
- 对话视图在一级视图切换时保持挂载，避免 `ChatView.vue:31-34,189-196` 的内存轮次丢失和卸载中止。
- 历史上限应成为前后端共享常量，避免客户端与 `src/server/router.ts` 再次漂移。
- Markdown 使用严格禁用原生 HTML 的同步 renderer；不在流式主链路引入 Shiki 等异步高亮器。

## 范围外

- 不重写应用或替换现有技术栈，不新增 Vue Router 或全局 store。
- 不实现跨刷新会话恢复、多会话管理、服务端知识库/外部导入持久化；现状证据保留在 `src/ui/views/ChatView.vue:31-34`、`src/server/context.ts:139-195`、`src/core/persist.ts:19-65`。
- 不实现段落级精确 citation ID，不扩展 SSE 终止原因协议。
- 不恢复此前主动移除的 Markdown/PDF 契约导出能力。
- 不引入 LLM 原生 HTML、任意第三方脚本或任意依赖 Demo 执行。

## 关键决策

- 采用聚焦核心体验的推荐范围，持久化能力延期。
- 知识库升级为一级工作区，而不是继续修补弹框尺寸。
- Markdown 采用 `markdown-it` 严格模式；首版不启用原生 HTML、DOMPurify 或 Shiki。
- 菜单优先使用 Element Plus 可访问组件，图标统一使用 `@lucide/vue`。
- 本任务作为一个端到端交付实施，不拆子任务；工作区与对话状态、响应式 E2E 需要统一集成验证。
