# ConfigForm 核心业务表单生产能力

## 目标与授权

已批准合同是唯一范围与验收依据：
[目标合同](../../../.pi/goal/基于成熟产品实测重建事件编排并完善-configform-核心能力-20260912-2011.md)。
用户已明确批准建立父/子任务并自主实施，不再次请求范围或实施审批。

本任务以 FormCreate Pro 实际发布产品交互为主、VForm 3 Pro 为辅，完成事件编排重写与核心业务表单闭环。覆盖现有 Element Plus 和 Ant Design Vue，允许 API/Schema 破坏性更改，不做兼容迁移；仅允许安全表达式和宿主注册动作，不执行任意 JavaScript。

## 背景

启动时存在 79 项工作区改动，主要归属 `09-12-config-form-event-architecture`。它们作为待复验的既有输入保留；该任务参考开源实现，不能作为本次商业产品交互调研的证据。此父任务不覆盖既有任务的历史记录，不撤销其改动。

## 范围边界

限定 ConfigForm 与必要集成/测试/文档/依赖；不做 AI、大屏、新增移动端库、服务端平台或正式发布。设计态/导入不得触发业务副作用；不访问受限商业源码，不绕过登录，不使用真实业务端点。不得清空用户持久化数据或 Git 历史，不推送远端或发布包。

## 子任务划分

- 产品证据与功能差距。
- 事件/变量/数据源共享运行合同与可视化配置。
- 嵌套明细及状态语义、双适配器集成。
- 导出等价、业务场景与集成质量门禁。

子任务的依赖、设计和验证记在各自 design.md / implement.md；父任务负责交叉验收。未验证项目保持未完成，环境或合同阻塞单独记录。
