# 国际化工具与共享 AI 配置

## 目标

为仓库新增一个可在用户项目本地启动的可视化国际化服务。服务读取用户配置中指定的本地资源目录，通过 AI 将源语言翻译为目标语言，并在该项目内创建或更新对应语言文件。工具应支持若干常见 Vue/JavaScript 国际化方案，同时将 AI 文档助手现有的 AI 供应商配置能力抽取为独立共享包，避免两个工具重复维护模型、鉴权与请求配置。

## 背景

- 用户需要通过本地 UI 操作配置、扫描、翻译和写回流程，而不是只使用配置文件或命令行。
- 用户确认原始描述中的 `vue18` 指 `vue-i18n`，并要求同时支持其他常见 JSON 国际化方案。
- AI 文档助手已有仅在服务端读取密钥、浏览器只消费脱敏状态的安全边界；共享 AI 能力必须保持该边界。
- 本地文件写回需要新增可预览、可检测冲突且不会静默覆盖的统一协议。

## 需求

### R1. 国际化工作台

- 提供 CLI 启动的本地 HTTP 服务，并自动或明确提示用户打开浏览器工作台。
- 服务读取用户配置指定的项目根目录和国际化资源目录；所有扫描与写回都限制在该授权范围内。
- UI 展示当前项目、适配器、资源目录、语言集合、源语言、目标语言和 AI 配置状态等配置项。
- UI 应能呈现资源扫描、待翻译内容、翻译结果、变更预览、冲突和错误状态。
- 工具采用独立可发布包 `@moluoxixi/i18n-tool`，提供包内 Vue UI、同源 Node BFF 与 CLI；文档站只提供说明和入口，不承载需要密钥或文件写回的核心应用。

### R2. 用户配置

- 项目配置文件是运行时事实源，默认发现 `i18n-tool.config.ts`、`.mts`、`.js` 或 `.mjs`，也可通过 CLI `--config` 指定。
- 配置至少包含项目根目录、国际化适配器、资源 include/exclude、资源布局、源语言、目标语言、目标文件命名规则、AI base URL/model/API key 环境变量名和本地服务选项。
- 配置内相对路径基于解析后的项目根目录；优先级为 CLI `--root` 高于 `config.root`，再高于配置文件目录。
- AI 密钥只通过配置指定的服务端环境变量名读取，不允许把密钥值写进配置文件或从浏览器提交。
- UI 展示服务端解析后的脱敏配置，并允许调整本次扫描、翻译和审阅参数；这些临时调整不反向修改项目配置文件。
- 提供纯类型辅助 `defineConfig()`；默认值填充、路径解析和运行时校验由独立 resolver 负责。

### R3. 国际化方案适配

- 通过明确的供应商/适配器边界支持多种常见国际化库。
- 不同库的解析、写回与配置差异不得泄漏到通用 UI 和翻译核心中。
- MVP 支持 Vue I18n JSON：locale-per-file，兼容 nested object 与 flat dotted keys。
- MVP 支持 i18next JSON：保留 namespace、plural 和 context 后缀语义。
- MVP 支持通用 JSON：兼容 locale-per-file 与 locale-first 单文件布局。
- MVP 不写回 TypeScript 资源；后续若支持，必须使用 AST 解析，带动态 spread、函数调用或 computed key 的资源只读或明确报不支持。

### R4. AI 翻译

- 支持使用已配置的 AI 模型生成或补全目标语言翻译。
- 翻译过程需要保留 key、插值变量、复数或富文本等不能被破坏的语义结构。
- UI 需要提供处理中、成功、部分失败、重试和可审阅结果等必要状态。
- 未经用户确认，不得静默覆盖已有译文。
- AI 输出必须通过运行时结构校验，并验证 key 数量、目标语言和占位符结构；不得通过类型断言信任模型 JSON。
- 用户取消必须从 UI 传播到 BFF 和上游请求；流式输出开始后不得透明重试并产生重复内容。
- 翻译输入来自服务扫描到的本地源语言资源；翻译结果通过目标适配器序列化，在指定资源目录内创建缺失的目标语言文件或更新现有文件。
- 默认只翻译目标语言中不存在或为空的条目，并按目标语言与资源文件批量执行。
- 结果以源文本、当前译文、候选译文和校验状态组成的可编辑表格呈现，用户可逐项或批量接受、拒绝和重试失败项。
- 已有非空译文默认不进入翻译批次；用户主动选择重译后，仍需在最终 diff 中再次确认覆盖。

### R5. 共享 AI 配置包

- 将可复用的非文档领域能力抽取为独立包 `@moluoxixi/ai-provider`，由 AI 文档助手与国际化工具共同消费。
- 抽取后不得破坏 AI 文档助手现有行为和配置兼容性。
- 密钥等敏感信息不得被打包进前端产物、日志或可提交配置。
- 共享包区分 server-only 密钥配置/传输与浏览器可用的脱敏 DTO，禁止 UI 导入含密钥的配置类型。
- AI 文档助手继续兼容既有 `AI_DOC_*` 环境变量、默认 base URL/model、chat key 必需及 embedding key 可选语义和现有公开导出。
- 共享包应提供通用 OpenAI-compatible chat transport、取消传播、稳定错误分类和脱敏；文档检索、prompt、来源协议及国际化翻译编排留在各自领域包。

### R6. 安全文件读写

- 浏览器只能提交服务端签发的相对资源 ID，不接受任意绝对文件路径。
- 服务端只扫描显式资源根，并同时执行词法路径与 canonical path 边界校验，拒绝越界和符号链接逃逸。
- 写回采用 `scan -> preview -> apply` 两阶段确认协议；preview 记录基线 hash，apply 时重新校验，过期变更返回冲突而不是覆盖磁盘。
- apply 前完成解析、schema/占位符校验、序列化和 round-trip parse，再通过同目录临时文件与 rename 原子写回。
- 请求需要限制 body 大小、文件数、总字节数、key 数和并发写回。
- 新建目标语言文件时遵循当前适配器的目录、文件名和 JSON 布局规则，不把不同供应商的命名约定硬编码到通用服务中。

### R7. 质量与兼容性

- 为供应商适配、资源解析/写回、占位符保护、AI 翻译编排和关键 UI 流程提供自动化测试。
- 新包与新工具遵循仓库现有 monorepo、构建、发布和类型检查约定。
- 对已有 AI 文档助手提供明确迁移路径，并保留必要的兼容层。

## 验收标准

- [x] 用户可在本地启动服务，服务读取用户配置指定的目录，并在浏览器 UI 展示已解析的项目配置与资源。
- [x] 默认配置发现、显式 `--config`、CLI 覆盖、运行时校验和脱敏配置展示符合约定。
- [x] 工具可识别首批支持方案的语言资源，展示缺失翻译，并生成可审阅的目标语言结果。
- [x] 用户确认后，工具可在授权目录内创建缺失的目标语言文件或原子更新现有文件。
- [x] AI 翻译不会破坏 key、插值变量及首批范围内约定的结构语义。
- [x] 已有译文不会在无明确确认的情况下被覆盖。
- [x] AI 配置能力位于独立共享包，AI 文档助手和国际化工具均通过该包使用同一套核心契约。
- [x] AI 文档助手原有配置和主要流程在迁移后保持兼容。
- [x] 敏感配置不会进入前端构建产物、日志或版本库。
- [x] 用户可在写盘前查看结构化变更与文本 diff；预览后文件变化会触发冲突，不会静默覆盖。
- [x] 越界路径、符号链接逃逸、超限请求和未经确认的写回会被服务端拒绝。
- [x] 单元测试、类型检查、lint、构建及关键 UI/E2E 验证通过。

## 暂定范围外

- 接入在线翻译管理 SaaS 或第三方 TMS。
- 托管式远程服务、多租户账号体系或云端项目存储。
- 自动提交、推送或创建 Pull Request。
- 无限制支持所有国际化库、任意动态代码执行和无法静态分析的资源声明。
- 首批支持 YAML、PO、ARB 等仓库当前没有证据的格式。
