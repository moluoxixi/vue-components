## 修正路由层级：从「项目 › 设计」改为「项目 › 页面 › 设计」

用户反馈上一版路由不对：「项目是项目，页面是页面，页面才对应表单设计器」。
确认后的三项决策：**层级嵌套**（项目 › 页面 › 设计）、**设计器地址粒度 `…/pages/:pageId/design`**、
**三类 Surface（page/dialog/drawer）共用同一套页面管理 + 设计器**。

### 路由表（替换掉上一版的 `/projects/:id/design/:surfaceId`）

| 路径                                        | name                            | 屏幕             |
| ------------------------------------------- | ------------------------------- | ---------------- |
| `/projects`                                 | projects                        | 项目管理（首屏） |
| `/projects/new` / `/projects/import`        | project-create / project-import | 新建项目         |
| `/projects/:projectId/pages`                | project-pages                   | 页面管理         |
| `/projects/:projectId/pages/new`            | page-create                     | 新建页面         |
| `/projects/:projectId/pages/:pageId/design` | page-design                     | 表单设计器       |

- 路径构造器：`projectPagesPath` / `pageCreatePath` / `pageDesignPath(projectId, pageId)`；
  旧的 `projectDesignPath` / `surfaceCreatePath` 已删除（无兼容别名，符合仓库硬切策略）。
- 路由参数从 `surfaceId` 改成 `pageId`（承载三类 Surface 的 id）；`WorkbenchRouteTarget = { projectId?, pageId? }`。
- `resolveWorkbenchSurfaceTarget` 删除，换成 `hasWorkbenchPage({ surfacesById }, pageId)`；命中不存在时
  回退到该项目的**页面管理**（不再静默打开首页）。

### 行为变化

- 项目管理点项目 → 进该项目的**页面管理**（不再直接进设计器）。
- 页面管理新增两个入口：标题区面包屑「项目管理」→ `/projects`；每行新增「打开设计器」按钮 → 该页设计路由。

- 新建页面成功后 → 进新页面的设计路由并聚焦 `[data-designer-entry]`；取消 → 回 origin 并恢复触发按钮焦点。

## 把「项目管理」「页面管理」做成两个平级管理台（用户反馈"一点都不好用，进不去"）

反馈原文：怎么进项目管理、怎么进页面管理，这不应该是真正的两个管理界面吗。
根因：项目管理只有开屏能到（回到它只能靠顶栏图标按钮 / 页面管理面包屑），页面管理在桌面端
只能从设计器左侧面板的 Surfaces 标签里摸到 —— 两个"管理界面"都没有常驻入口。

### 新增

- `src/app/components/ManagementShell.vue` + `ManagementShell/style/index.css`：共享管理台外壳，
  左侧导航栏（≤700px 变顶部横向条）列出两个管理台，当前台带 `aria-current="page"`，
  暴露 `data-management-target` 便于测试。样式已接入 `src/styles/index.css` 级联清单与
  theme-contract 归属表（两处都要一起改）。
- `src/app/composables/use-workbench-management-nav.ts`（+ 类型 `WorkbenchManagementTarget`
  放在 `src/app/types/management.ts`）：`active`（按路由判定）+ `select(target)`。
  页面管理命令会优先用当前项目，其次用最近更新的项目；工作区为空时 notify 并留在 /projects。
- `ProjectsView` / `PagesView` 都包在 `ManagementShell` 里 → 两台一键互达；设计器不渲染该导航
  （因此 1440px 视觉基线不受影响）。
- 布局联动：`.management-shell { height:100vh; display:flex }` → `.project-manager` 加
  `flex:1; min-width:0`，`.page-manager-page` 由 `min-height:100vh` 改 `flex:1; min-height:0`，
  SurfaceManager 的 `.page-manager` 由 `min-height:100vh` 改 `min-height:0`（否则会撑出视口）。
- locale 新增 `nav.management`（管理/Management）、`nav.noProject`。

## 页面管理改为"默认只读 + 链接式跳转"

用户反馈：页面管理还需要优化，应该默认不能编辑，跳转可以考虑用在线链接的样式。

- 行默认**只读浏览态**：页面名是文本（`.page-manager__name`），路由改成**链接样式**的按钮
  （accent 色 + ↗ 图标 + hover 下划线 + title/aria-label "在设计器中打开 {name}"），点击 = 打开该页设计器；
  弹窗/抽屉行（无路由）同一位置显示「打开设计器」链接文字。原来那个铅笔图标"打开设计器"按钮删除，
  换成「编辑」按钮（编辑态变「完成」✓）。
- 编辑态由 `editingId` 驱动：name/route 才变成 ElInput（autofocus 名称），
  行级 `@keydown.esc="cancelEdit"` 取消且不发命令；`beginEdit` 会先 `finishEdit()` 提交上一行（避免切换行丢编辑）。
  inputs 现在只在编辑态存在，`<label role="cell">` 改成 `<div role="cell">`（无控件时 label 语义不成立）。
- 词条新增 `pageManager.edit/editAria/finish/finishAria`（en/zh 同步，目录现 453 条对称无缺失）。

### 坑：Esc 只在输入框上监听不够

e2e 里点「编辑」后立刻 `keyboard.press('Escape')` 偶发不生效 —— 焦点可能还在刚点的按钮上，
按键没进到输入框。把 `@keydown.esc` 提到**行级**（原生冒泡）后，行内任何焦点位置都能取消；
单测用 `trigger('keydown', { key: 'Escape' })` 覆盖。调试手法：写一次性 Playwright 脚本打印
`document.activeElement` 与编辑态输入框数量（单独跑是通的 → 说明是时序/焦点问题，不是逻辑问题）。
